Instalar CoCo Desktop

Snowflake CoCo es un agente de código impulsado por IA. Es una app nativa Mac/Windows con editor de archivos, terminal integrado, navegador agéntico y capacidades de IA que conocen tu cuenta de Snowflake.

  1. Descarga CoCo Desktop desde el portal de Snowflake
  2. En el primer inicio, sigue el wizard de onboarding
  3. Haz clic en Next en la pantalla de bienvenida
  4. Agrega tu conexión (mismo account identifier y credenciales de tu cuenta trial) o selecciona una existente detectada de connections.toml
  5. Elige modo Agent
  6. Escoge tu tema, luego haz clic en Get Started
Tip Si ya configuraste una conexión con snow connection add, CoCo Desktop la detecta automáticamente — solo selecciónala de la lista.

6Calidad de Datos (DMFs)

~5 minutos

Las Data Metric Functions (DMFs) adjuntan verificaciones de calidad automáticas a columnas. Built-in: NULL_COUNT, DUPLICATE_COUNT, UNIQUE_COUNT, FRESHNESS.

El setup inyectó ~200 NULLs en total_amount y quantity, más ~150 en product_name. Los DMFs detectan los primeros dos — pero hay un hueco.

Descubrir el Hueco

Prompt CoCo:

“Revisa los resultados de monitoreo de calidad de datos y muéstrame qué columnas tienen violaciones de NULLs”

CoCo muestra TOTAL_AMOUNT (200 NULLs) y QUANTITY (200 NULLs) — pero product_name pasa desapercibido.

Prompt CoCo:

“Hay valores NULL en order_items.product_name? Esa columna está siendo monitoreada?”

Corregir

Prompt CoCo:

“Corrige el DMF — remueve la verificación de NULLs de product_category y agrégala a product_name”
ALTER TABLE order_items DROP DATA METRIC FUNCTION SNOWFLAKE.CORE.NULL_COUNT ON (product_category); ALTER TABLE order_items ADD DATA METRIC FUNCTION SNOWFLAKE.CORE.NULL_COUNT ON (product_name);
Flujo real Monitorear → descubrir huecos → corregir cobertura.

10Seguridad: Row Access Policies

~5 minutos

BUILD 4 — Confianza y Acceso

Las Row Access Policies aplican seguridad a nivel de fila de forma declarativa — transparente para cada query, incluyendo las generadas por agentes de IA.

Como ACCOUNTADMIN (acceso completo):

USE ROLE ACCOUNTADMIN; USE WAREHOUSE HOL_WH; SELECT c.state, SUM(o.total_amount) AS total_revenue, COUNT(DISTINCT c.customer_id) AS customer_count FROM dash_automated_intelligence_db.raw.orders o JOIN dash_automated_intelligence_db.raw.customers c ON o.customer_id = c.customer_id GROUP BY c.state ORDER BY total_revenue DESC;

Resultado: 10 estados visibles.

Como WEST_COAST_MANAGER (restringido):

USE ROLE WEST_COAST_MANAGER; USE WAREHOUSE HOL_WH; SELECT c.state, SUM(o.total_amount) AS total_revenue, COUNT(DISTINCT c.customer_id) AS customer_count FROM dash_automated_intelligence_db.raw.orders o JOIN dash_automated_intelligence_db.raw.customers c ON o.customer_id = c.customer_id GROUP BY c.state ORDER BY total_revenue DESC;

Resultado: solo CA, OR, WA.

Mismo query, mismas tablas, resultados diferentes La seguridad funciona transparentemente, incluso a través de SQL generado por agentes de IA.

Verificar en CoWork

Configura password para el usuario demo y prueba el agente con ese rol:

ALTER USER west_coast_manager_user SET PASSWORD = '<tu-password>';

Inicia sesión como west_coast_manager_user, abre CoWork y pregunta:

Prompt CoCo:

“Cuál es nuestro ingreso total y conteo de clientes por estado?”

El agente retorna solo CA, OR, WA — la Row Access Policy filtra datos incluso a través de IA.

11Evaluación del Agente

~10 minutos

La Evaluación de Agentes mide calidad usando ground truth y LLM-as-judge: Answer Correctness y Logical Consistency.

Ejecutar en Snowsight

  1. Cambia al rol ACCOUNTADMIN
  2. Navega a AI and ML > Agents > BUSINESS_INSIGHTS_AGENT > Evaluations
  3. Clic Use existing dataset → Run an eval manually
  4. New evaluation run, nombre: hol-eval-run-1, clic Next
  5. Create new dataset from table → DASH_AUTOMATED_INTELLIGENCE_DB.SEMANTIC.AGENT_EVALUATION_DATA
  6. Dataset name: hol_eval_dataset, clic Next
  7. Activa Answer Correctness (Expected answer = GROUND_TRUTH) y Logical Consistency
  8. Clic Create — ~3 min para completar

Observabilidad del Agente

-- Pasos de razonamiento y tokens SELECT RECORD:name::STRING AS step, RECORD_ATTRIBUTES:"snow.ai.observability.agent.planning.model"::STRING AS model, RECORD_ATTRIBUTES:"snow.ai.observability.agent.planning.token_count.input"::INT AS input_tokens, RECORD_ATTRIBUTES:"snow.ai.observability.agent.planning.token_count.output"::INT AS output_tokens FROM TABLE(SNOWFLAKE.LOCAL.GET_AI_OBSERVABILITY_EVENTS( 'DASH_AUTOMATED_INTELLIGENCE_DB', 'SEMANTIC', 'BUSINESS_INSIGHTS_AGENT', 'CORTEX AGENT' )) WHERE RECORD:name::STRING LIKE 'ReasoningAgentStep%' ORDER BY TIMESTAMP DESC LIMIT 10;

openssl genrsa 2048 | openssl pkcs8 -topk8 -inform PEM -out rsa_key.p8 -nocrypt openssl rsa -in rsa_key.p8 -pubout -out rsa_key.pub snow sql -q "ALTER USER <tu-usuario> SET RSA_PUBLIC_KEY='$(grep -v -- '-----' rsa_key.pub | tr -d '\n')'" -c hol
